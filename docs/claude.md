This turned into a fairly deep research pass — I pulled the Stack Overflow survey data, the Vim Adventures site itself, Similarweb traffic estimates, user reviews across HN/Trustpilot/dev.to, the competitor landscape (web and mobile), the motor-learning literature on touchscreen skill transfer, and current Codex pricing. Here is the full analysis. I have kept the opportunity analysis (sections 1–6) strictly independent of your mobile idea, which I evaluate separately in section 7, as you asked.

## 1. Is Vim still relevant in 2026, and what is the trend?

The usage data is more positive than you might expect. Vim reported 24.3% usage in the 2025 Stack Overflow survey, up from 21.6% in 2024, and Neovim recorded 14%, for a combined 38.3% among developers — this against VS Code at 75.9% (the survey is multi-select, so these overlap heavily: many "Vim users" are VS Code users with a Vim plugin, which is exactly your case). Cursor entered the survey at 17.9% and Claude Code at 9.7%, the fastest editor debuts ever recorded, while terminal editors still matter: Vim 24.3% and Neovim 14% together rival the big graphical IDEs. Notably, Neovim achieved 83% admiration in the 2024 survey, the highest rating among all development environments — people who adopt it stay enthusiastic. The main VS Code Vim extension alone had around 8 million downloads as of late 2025.

The more important question is the *interpretation* under AI. The honest split of opinion: one camp argues the marginal gains of manual editing speed shrink when agents write most code — a recent HN poster admitted his motivation was partly ego and suspected the marginal gains would disappear when more of the work is delegated to AI, "why would I learn Vim if I'm just going to be prompting Opus all day". Even a committed convert wrote that in the wake of AI agents, the gains from learning Neovim are diminishing because he writes less code manually and relies on agents for refactors. The other camp — which I find more analytically sound — notes that AI shifts your time from *writing* to *reviewing, navigating, and surgically correcting* generated code, and that is precisely where motions shine: once mastered, Vim excels at code navigation and review of AI-generated code, though achieving proficiency demands discipline when AI tools dominate. There is also a structural tailwind: agentic tooling is terminal-centric (Claude Code, Codex CLI, opencode), which has pulled developers back into terminals where modal editing is native — even Claude Code has a vim mode.

My prognosis: Vim *the standalone editor* is a stable niche (community-maintained since Bram Moolenaar's death, with Neovim carrying the innovation momentum). But "Vim motions as a portable input language" — embedded in VS Code, JetBrains, Zed, Cursor, terminal agents — is the durable asset, and its host surface is growing, not shrinking. The population of people *wanting to learn* it is probably flat to slightly declining over 5 years, but it will not collapse; it is a permanent minority skill with strong cultural transmission (the ThePrimeagen/streaming ecosystem keeps recruiting new learners). For your personal decision: learning the motion/operator grammar has a long shelf life; learning Vimscript configuration and plugin ecosystems does not (you don't need them in VS Code anyway).

## 2. Is "learning Vim specifically to automate edits" reasonable?

Yes, but with an important precision: the subset of Vim that automates predictable edits is *not* the subset most trainers (including Vim Adventures) teach. The automation toolkit is: the dot-repeat operator (`.`), counts (`3dw`), macros (`qa...q`, `@a`, `@@`), the ex commands `:s` with regex and `:g`/`:v` (run a command on every matching line), `:normal` (apply normal-mode keystrokes across a range), and visual block mode (`Ctrl-v`) for columnar edits. Navigation fluency (`f`, `t`, text objects, `%`) matters mainly as the *building blocks inside* macros and repeats.

Your three-way latency framework is correct, and I would sharpen the decision boundary like this. Manual Vim (dot-repeat, macro) wins when the edit is regular in *structure* but the instances number roughly 3–200 and live in one or a few open files — the fixed cost is ~5 seconds to record a macro, and there is no verification burden because you watch each application. An LLM edit wins when the transformation requires judgment (renaming with semantic understanding, restructuring), or spans many files, and you can tolerate 30–120 seconds of round-trip plus review. A generated Python/sed script wins when the edit is mechanically specifiable, spans the repository, and you want a reviewable, re-runnable artifact. Note also that in VS Code you already have a fourth tool that eats much of the middle ground: multi-cursor (`Cmd+D`, `Alt+Click`) and regex find/replace — one convert who tried full Neovim concluded that macros are amazing, but multi-cursor is an intermediate compromise that solves 99% of his problems much faster. So the genuinely differentiated Vim value for you is: dot-repeat (zero-setup repetition), macros over *irregular* structures where multi-cursor fails (instances that need per-instance navigation), and `:g`/`:normal` for line-predicated batch operations. That is a real, learnable, compact skill — but be aware it is exactly the tail that gamified trainers cover worst.

One VS Code-specific caveat: VSCodeVim is a from-scratch reimplementation that uses Neovim only optionally, for ex commands like :substitute and :global, and its macro implementation is known to be slow and to corrupt the undo stack — macros execute serially with view updates each time, and hitting undo after a macro "is like rolling the dice". If automation is your goal, the better host is vscode-neovim, which uses a fully embedded Neovim instance — feature-complete Vim integration except insert mode, with VS Code handling insert, LSP, autocompletion and multi-cursor. That gives you real macros, real `:g`, real regex, inside VS Code.

## 3. Vim Adventures: deep dive

The game, created by Doron Linder in 2012 and still maintained (copyright notice runs through 2026), is an online puzzle game based on Vim's keyboard shortcuts — "Zelda meets text editing" — where you play a blinking cursor in Textland, collecting keyboard buttons that each add a command to your repertoire, and you cannot advance until you master a skill. Pricing today: a Game-Only license at $35 for 6 months of access covering more than 60 commands across 13 levels, or a Game & Challenges license at $40 which adds timed CTF challenges and a level teaching macros. The first three levels are free; the price has crept up over the years (HN commenters were citing $25 for a 6-month license as recently as ~2024/2025).

**Coverage — what it does well.** From the site's own taught-commands list: it is excellent on the navigation and operator grammar — `h j k l`, word motions `w W e E b B`, character search `f F t T ; ,`, line anchors `0 ^ $`, screen and file motions `H M L gg G z zt zz zb %`, paragraph/sentence motions, counts, search `/ ? n N * #`, the operators `d c y` with `x r ~ s S o O i I a A`, dot-repeat, marks and jumps, undo/redo, and — genuinely its strongest and most unusual asset — a *very* thorough treatment of registers (named, numbered, black-hole) and text objects (`iw aw i( a( i" a" it at i{ ...`). Text objects plus dot-repeat are the highest-leverage part of Vim for a VS Code user, and almost no other trainer teaches registers at this depth.

**What it misses.** Reading the same list against full Vim, the gaps are stark: no visual mode at all (`v`, `V`, and critically `Ctrl-v` visual block — arguably the most-used feature by modern plugin users), no `:s` substitution, no regex, no `:g`/`:v` global commands, no `J` (join), no case operators beyond `~`, no windows/splits/tabs, no jumplist (`Ctrl-o`/`Ctrl-i`), no folds, no configuration, no plugins. And macros (q, @) are covered only by the paid challenges tier, not the main game. In other words: **the automation subset you specifically want — macros, :s, :g, regex, visual block — is almost exactly the part Vim Adventures does not teach.** A second structural weakness: the exercises are prose and pop-culture texts, not source code, so you never practice motions against brackets, function signatures, or indentation — the actual terrain of your daily edits.

**Fit with VS Code Vim plugins.** Here the picture is mixed in an interesting way. The game *omits* the things a VS Code user genuinely doesn't need (buffer/file management `:w :e :b :ls`, splits, configuration — VS Code handles these), so little of your license fee is wasted on irrelevant material; conversely its register/text-object depth transfers fully to both VSCodeVim and vscode-neovim. But it also omits visual mode, which is heavily used in plugin workflows, and the ex-command automation layer which is precisely what vscode-neovim exists to provide. So it teaches the "fluent hands" layer well and the "bulk edit" layer almost not at all.

**Web UI pros and cons.** Pros: zero install, instant start in any browser, forced mastery gating, an in-game `:help` system that mirrors real Vim's, and command-line-mode menus (`:level`, `:keyboard`, `:stats`) that themselves reinforce ex-command habits. Cons, well documented by users: game logic runs server-side, so it is online-only with visible input latency — one frustrated developer wrote that it's an online-only live service game that will go down once the servers are shut down, and the server-side game logic means it handles with the grace and elegance of a Stegosaurus in a gift shop; sessions expire (you often have to re-login and reload your saved game if you've been away for a while); the artwork is 2012-vintage CC assets; and — decisive for your later idea — the site actively refuses mobile devices with a screen saying "This game requires a keyboard. A physical keyboard."

## 4. Traffic and sentiment trend

Traffic is modest and gently declining. Similarweb's snapshot around November 2024 showed 62.8K total monthly visits, a 51.5% bounce rate, 1.53 pages per visit and an average visit duration of 26 seconds, at global rank ~#650,449; by June 2026 the global rank had slipped to #809,072 (#13,890 in Programming and Developer Software), with organic search driving ~35% of desktop visits. A rank decay of ~25% over 18 months, combined with that 26-second average duration (most visitors bounce off the landing page; the paying, playing core is a small fraction), indicates a mature product coasting on SEO and word-of-mouth rather than growing. Its ecosystem neighbours are similarly small: openvim.com at 22.5K monthly visits, vimgenius.com at 39.1K, vimsnake at under 1K (Nov 2024).

Sentiment has been remarkably stable for a decade, and stably *bimodal*. The positive pole: people credit it with actually working — "I learned vi(m) using vim-adventures... I felt I got my money's worth and continue to use and love vi(m) to this day", and it keeps being recommended organically on HN year after year. The negative pole has two constant complaints. First, the licensing: since at least 2015 people have said "I can not justify $25 for a game I can only use for 6 months, but I will pay $25 once off", and even fans concede "the creator does himself a disservice by selling 6 month licenses rather than lifetime... it only took me a couple days to play through". Second, pedagogy in the late game: "the later levels turn into overcomplicated puzzles — instead of building VIM muscle memory, you end up stuck figuring out how to solve the puzzles themselves". The pricing resentment is strong enough that it has literally spawned competitors: one developer announced a free GPL alternative explicitly because a $35 license for a game with "the graphics and gameplay quality of a free itch.io game" felt like "daylight robbery". Meanwhile a new generation of free or cheap trainers has filled the space: VimVenture (54 free keystroke-golf puzzles, speedruns, daily challenge, no install or account), VimGym (interactive exercises, progress analytics, leaderboards, free tier), VimSanity, plus the paid-course entrant VimHero (50+ interactive lessons with per-skill proficiency tracking), alongside the old guard of vimtutor, OpenVim and VimGolf. Verdict: the incumbent's brand is durable but its product is stagnant, its pricing model is its best-known flaw, and its traffic is eroding.

## 5. If you built an alternative: would it be relevant, and how much money?

Relevance: yes, the demand signal is real but small. There is a steady inflow of learners (the SO survey shows 39% of 18–24-year-old developers want "coding challenges" as a content format, and 35% of respondents have been coding under 10 years), and the incumbent has visible, decade-old weaknesses. But be sober about scale: the *category leader* gets ~60K visits/month with a ~50% bounce. This is a niche of niches.

Income, estimated transparently. For Vim Adventures itself there is no public revenue data, so here is the back-of-envelope: of ~60K monthly visits, perhaps 1,000–3,000 people per month seriously play through the free levels (consistent with the 26s average duration dragging the mean down); freemium conversion of engaged users to a $35 purchase plausibly runs 3–10%, giving 30–300 sales/month, i.e. roughly $1K–10K/month. The fact that a solo developer has kept it running and updated for 14 years suggests the true figure is comfortably inside that range — a decent lifestyle side business at near-zero marginal cost, not more. For *you*, entering as a newcomer against a known brand plus multiple free alternatives, with no existing audience: my honest estimate is $0–300/month in year one as the modal outcome, $1–2K/month as a good outcome contingent on a strong Show HN / Reddit / ProductHunt launch and continued content marketing, and anything beyond that requiring either virality or an adjacent distribution channel (e.g. a popular blog or the streamer ecosystem). Treat revenue as a bonus, not a plan.

**Differentiators — the unmet needs (derived before, and independently of, your mobile idea).** Four gaps fall directly out of the analysis above. First, *retention as a first-class system*: no existing Vim trainer does scheduled review — they are all linear curricula or golf challenges — yet the core failure mode, which you yourself named, is forgetting infrequently used commands. A trainer that models per-command memory and schedules micro-drills is genuinely novel in this niche. Second, *the automation curriculum*: macros, `:s`, regex, `:g`, `:normal`, visual block — the "bulk predictable edits" toolkit is taught by nobody in gamified form (the incumbent paywalls macros into challenges and omits the rest entirely). "Learn to do in 8 keystrokes what others do with 40 clicks" is a sharper value proposition than "learn to move around". Third, *real code as terrain*: exercises on actual source files (brackets, camelCase, indentation, per-language idioms), fixing the Trustpilot complaint that late-game content trains puzzle-solving rather than editing. Fourth, *closing the transfer gap with telemetry*: a companion VS Code/Neovim plugin that observes your real editing, detects inefficiencies (e.g. you pressed `x` eleven times where `daw` existed), and feeds them back as personalized drills — no competitor connects training to actual editor behaviour. On the business-model side, the obvious fixes are one-time or free+pro pricing (the single most-criticized aspect of the incumbent) and a fully client-side, offline-capable engine (fixing the second-most-criticized).

## 6. Your mobile idea, evaluated separately

**Would the skill transfer from an on-screen keyboard?** The motor-learning literature gives a nuanced but usable answer. Layout knowledge transfers partially: a controlled study found a moderate positive correlation (r ≈ .5) between touch-typing speed on a physical keyboard and entry speed on a soft QWERTY keyboard — but essentially no transfer (r < .1) when the layout is unfamiliar, so spatial knowledge of where keys live crosses the boundary, in both directions. However, the finger-level motor program does not: ten-finger typing experience stored in muscle memory and tactile feedback enables eyes-free typing on physical keyboards, but this knowledge does not successfully transfer to soft keyboards due to lack of tactile feedback, and the largest mobile-typing study (37,000 users) concluded that touchscreen typing is a motor skill people learn on its own, with no benefit found from formal training on the ten-finger system for physical keyboards.

Translated to your case: what a phone app can genuinely build is the *cognitive* layer of Vim — command vocabulary, the operator+motion composition grammar, "which tool for which edit" decision-making, and chunked sequences (knowing `ci(` as a single unit). That layer is, honestly, the larger part of Vim competence and the part you keep forgetting. What it cannot build is the literal home-row hand mechanics — that final 20% still requires desktop repetitions. So the intellectually honest positioning is "grammar and recall trainer that makes your desktop practice 5x more efficient", not "muscle memory on the train". This framing matters because it is true, and because a false "muscle memory" promise would generate exactly the kind of negative reviews the quiz apps get.

**Is the niche empty?** Thin, but not empty — and validated. Vim Adventures itself hard-blocks mobile visitors with its "physical keyboard required" screen, meaning every mobile visitor it attracts today is turned away unserved (I could not get a reliable mobile-share number for its traffic; for developer content 15–30% mobile is typical). On Google Play there are two notable attempts: a quiz app, Vim Master, which uses 4-choice questions with badges and difficulty levels and whose top critical review argues that some "solutions" teach bad habits, making it "actively harmful to anyone trying to learn VIM" (multiple-choice is the wrong interaction model — worth internalizing); and VimKata, much closer to a good product: 135 exercises across 7 levels (motions, editing, operators+motions, text objects, visual mode, navigation, quick edits), every keystroke scored S-to-D with the optimal solution shown afterwards, levels 1–3 free and the rest a one-time purchase, framed explicitly as "Vim is a language — operators compose with motions". VimKata is your real competitor and also your proof of demand. What does not exist anywhere on mobile is the *Vim Adventures formula* — a narrative world with progression — nor anything with a retention/spaced-repetition system, nor anything covering the automation subset. Note the convergence: the differentiators derived independently in section 5 (retention, automation curriculum, real code) all remain unclaimed on mobile too.

**Input design.** Do not ship a miniature full QWERTY — Vim is symbol-heavy (`$ ^ { } : @ Ctrl`) and tiny soft keys will make it miserable. Build a purpose-made command keyboard: a large-key layout of the Vim alphabet arranged in true QWERTY *positions* (so the r≈.5 spatial transfer works for you), with a shift layer for symbols, and generous hit targets. Two-thumb interaction is the ergonomic sweet spot — that is how users reach ~38 wpm on phones, only ~25% slower than typical physical-keyboard speeds — and Vim commands are short bursts, not sustained prose, which suits thumbs even better than typing does. For truly one-handed commute moments, degrade gracefully to "compose the command from large chips" (pick operator, then motion) rather than multiple choice — it preserves the compositional thinking that quizzes destroy.

**Graphics.** Keep the 2D tile world — it is the emotional differentiator over kata/drill apps, it is cheap (especially now that you can generate tile sets and character art), and it survives on small screens. One structural suggestion: consider a *turn-based roguelike* framing rather than a real-time Zelda one. A roguelike is a grid where each keypress is one discrete action — which is literally what Vim is — and it naturally accommodates counts (`3j` = move 3), operators as attacks over motions as ranges, and procedurally generated dungeons. It is also the genre most tolerant of modest art.

**Users and money.** Realistically: a polished free mobile Vim game with a one-time unlock (learn from VimKata's model and the incumbent's pricing resentment — never rent) might reach 10K–100K lifetime installs if launch goes well (HN, r/vim, r/neovim, ProductHunt, and the streamer ecosystem are the channels; App Store search for "vim" is low-competition). At a 2–5% conversion to a $6–10 unlock, that is roughly $1K–50K lifetime, with the mode in the low thousands. Same conclusion as the web case, slightly better discovery dynamics: portfolio piece plus pocket money, not income.

**LLM-generated worlds — yes, and this is the best part technically.** Vim puzzles are the ideal case for LLM content generation because the "world" *is text*: a level is (initial buffer, target buffer, allowed key set, par). The pipeline is: LLM generates themed content and edit specifications → a deterministic Vim emulator (this must be client-side and yours; it is the core engine anyway) validates solvability → an optimal-solution search (BFS/A*/beam over editor states with the allowed key set) computes par and canonical solutions. That solver is a genuinely interesting algorithmic artifact by itself, and it gives you automatic difficulty calibration and the "here is the 4-keystroke way you missed" feedback that VimKata does manually. Personalization of themes is then trivial and cheap — generated per-user at cents per level, or pre-generated in batches. (Tango-lyrics-themed levels for one user, Kafka for another.)

**The ML/data-science angle — legitimately strong, and this is where I would anchor the project.** You would be sitting on keystroke-level interaction logs mapped to a clean skill taxonomy (each command/composition is a skill), which is the exact substrate of educational data mining. Concretely: (a) *knowledge tracing* — model P(correct | history) per skill, from Bayesian Knowledge Tracing baselines up to Deep Knowledge Tracing and transformer variants (SAKT/AKT), used to drive exercise selection; (b) *memory modelling and scheduling* — this niche's state of the art is FSRS, a data-driven scheduler with a three-component memory model (Difficulty, Stability, Retrievability) and 19 trainable weights that predicts when a learner will forget and schedules reviews accordingly, which benchmarks on 500+ million Anki reviews show needs 20–30% fewer reviews than SM-2 for the same retention, and which Anki adopted as default in 2023 — fitting FSRS-style parameters to *procedural command recall* rather than declarative flashcards would be a genuinely novel small study; (c) *scheduling as sequential decision-making* — there is active research applying deep RL with transformer-based models to refine repetition scheduling and RL-plus-cognitive-model approaches like SSP-MMC, with recent work even using LLMs for semantic-aware scheduling (LECTOR), so you would be building on a live literature, not a dead one; (d) *weakness diagnosis* — the gap between a user's keystroke sequence and the solver's par is a per-skill inefficiency signal nobody else has (VimGolf has it implicitly but no learner model on top). And the meta-layer connects straight to your evaluation-science lane: defining the target metric (retention? in-editor transfer measured by the companion plugin?), designing offline evaluation of the scheduler against logged data — which is off-policy evaluation, the same machinery you studied for ads ranking — and running honest A/B comparisons of FSRS vs. DKT-driven vs. heuristic scheduling. That is a publishable workshop paper and two or three strong blog posts ("Knowledge tracing for a command language", "Does FSRS work for motor-adjacent skills?", plus a released anonymized dataset). As portfolio material it is *stronger* than the game itself, because it demonstrates measurement thinking on a system you fully own.

## 7. Cost of vibe-coding it with Codex from zero

Codex is now included across ChatGPT plans with token-based credit billing (switched from per-message in April 2026): Plus at $20/month is the first practical individual tier; the Pro tier gives either 5x ($100) or 20x ($200) higher usage than Plus, and the practical characterization is that Plus supports a few focused coding sessions each week. OpenAI's own estimate for professional use is ~$100–200 per developer per month on average, with large variance depending on model, instances, and fast-mode usage. The alternative is API-key billing: at $0.50–2.00 per session, an API key beats Plus below roughly 10–40 sessions per month.

For this specific project: an MVP (Vim emulator core + solver + ~30 exercises + basic UI, web-first even if the target is mobile — a PWA or a Capacitor/React Native wrapper later) is realistically 60–120 agent sessions over 6–10 weeks of evenings. On Plus you will hit the 5-hour-window limits during intense weekends — users report the "5 hours" allowance can be exhausted in about one hour on a serious repository — so budget either Plus + patience (~$60 over 3 months), Pro 5x for the build months (~$300), or API-key usage (~$100–250 total for the MVP at per-session rates). Add fixed costs: Apple developer program $99/year, Google Play $25 one-time, hosting near-zero if the engine is client-side (which it should be — that is also the fix for the incumbent's worst flaw), and LLM level-generation at cents per level in batch. All-in cash cost to a shipped MVP: roughly **$150–500**. The real cost is the 100–200 hours of your attention, and one caution from experience with agentic builds: the Vim emulator's correctness is the one component you should not fully vibe-code — drive it with a test suite derived from real Vim behaviour (there are existing conformance test ideas in projects like VimVenture/monaco-vim you can study), because subtle emulation bugs are precisely what earned the quiz apps their "teaches bad habits" reviews.

## Bottom line

Vim motions remain a durable, slightly counter-cyclical skill in 2026 — more valuable for reviewing and surgically correcting AI output than the "AI makes it obsolete" take suggests — and your specific goal (automating predictable edits) is reasonable, though it targets exactly the macro/:g/:s/visual-block subset that Vim Adventures and nearly all gamified trainers skip. Vim Adventures itself is a well-loved but stagnating incumbent: ~60K declining monthly visits, 14-year-old server-bound architecture, a universally resented 6-month license, excellent coverage of motions/registers/text-objects, and near-zero coverage of automation. The commercial opportunity for an alternative is small (low thousands per month in a good scenario); the *portfolio* opportunity is real and specific: a mobile-first, roguelike-styled trainer with an honest "command grammar and recall" positioning, LLM-generated solver-validated levels, and — the part I would lead with — an FSRS/knowledge-tracing-driven adaptive practice engine with published evaluation. That last piece converts a fun side project into evidence of exactly the measurement-science profile you have been interviewing on. The one strategic caution: this is a 3+ month attention commitment, so it competes directly with the evaluation-science writing lane you already prioritized — the cleanest reconciliation is to scope the first milestone as "emulator + solver + FSRS scheduler + a blog post with real retention data from N=1 (you)", which is shippable in weeks and tells you whether to continue.
